RAG and QA Metrics

If you ask an LLM directly what time it is, it will likely say some random time from when it was trained

However, if you insert into your prompt what the current time is, it will say the correct time

LLMs are excellent at generating a likely piece of text, given previous text

But they're limited to their training data

RAG is a way to provide context to the LLM

We use RAG to retrieve relevant KB topics and insert them into the system message

Misonception about "hallucination" - every token generated by the LLM is a hallucination, but we can use RAG to improve the relevancy of the hallucinations

Why do we need RAG?

Direct LLM Query (no context)

User: "What time is it?"
LLM: "It's 12:42 on June 14 2023..."

RAG Query

User: "What time is it?"
System: "Answer the user's question, given that the current time is 2:30 PM"
LLM: "The current time is 2:30 PM"

What is Retrieval-Augmented Generation?

  • Retrieval: Find relevant content from the knowledge base
  • Generation: Use that content to augment the prompt

Retrieval Step 1: Embedding

  1. Embed all KB topics ahead of time
  2. Store embeddings in a vector db (we use RedisDB)

Every topic will have at least 1 embedding (topic_name + topic_content)

Plus a separate embedding for each sample_query

Retrieval Step 2: Cosine Distance

  1. Take the user_input (query vector) and compare it to the embeddings for all the topics
  2. For example, say our query vector was Ada is the cute pair programmer and our first topic was "Ada Lovelace was the world's first programmer"
  3. Get the embeddings for each (only doing 2d here for simplicity)
  4. These can be visualised in N-dimensional space
  5. What we want is to calculate how similar these 2 vectors are. One way of defining similarity is measuring how big the angle between them is
  6. The smaller the angle, the more similar the vectors are
  7. To calculate cosine distance, we do 1 - cos similarity
  8. To calculate cos similarity, we do the dot product of the 2 vectors divided by the product of the magnitudes of the 2 vectors
  9. Eventually, we get a number between 0 and 2
  10. The exact same vectors would have a cosine distance of 0
  11. Vectors with no correlation have a cosine distance of 1

Retrieval Step 3: Find closest topic(s) under threshold

We repeat calculating cos distance between the user_input and all the topics (NOTE: currently only the closest score for a topic is returned, we don't know whether that was for the topic_name_name or sample queries) - that's why i made my tool

End up with a sorted set of topics - filtering out topics with a cosine distance greater than the threshold

Finally, we insert these into the system prompt shown earlier
