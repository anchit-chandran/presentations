RAG and QA Metrics

How PolyAI uses Retrieval-Augmented Generation

Why do we need RAG?

  • Example: Ask LLM “What time is it?”
  • LLM guesses – output may be incorrect
  • Now prepend correct time to prompt – LLM gives correct output
  • Takeaway: Prepending relevant info improves output
  • "Hallucination" is a misnomer – all output is generative, but RAG improves relevancy
  • Agent Studio uses RAG to retrieve and prepend relevant knowledge base topics
  • We log QuestionAnswer metrics with cited_topics for analytics

What is RAG?

Retrieval-Augmented Generation = Retrieval + Generation

  • Retrieval: Find relevant content from the knowledge base
  • Generation: Use that content to augment the prompt

Prompt construction for each turn:

Retrieval

  • Step 1: Embed all KB topics ahead of time
  • Store embeddings in RedisDB
  • Embedding = vector of numbers representing the content

Example: "Ada is the best" → embedding vector

Embedding Structure

  1. Encode topic name and full content separately
  2. Combine using np.add (element-wise)
  3. Encode each sample question individually for question-time retrieval
